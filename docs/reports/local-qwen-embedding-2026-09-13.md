# 로컬 Qwen 임베딩 적용 — 2026-09-13

## 결론

사용자가 지정한 `Qwen/Qwen3-Embedding-0.6B`를 로컬 Mac의 MPS에서 실행하고,
기존 로컬 DB `127.0.0.1:5433/ai_sns`의 캐릭터 기억 125개를 재임베딩했다.
1024차원·모델명·내용 SHA256 일치를 125/125 확인했다. 웹의 기본 컨테이너를 사용한
4개 캐릭터 요청 준비에서도 의미 검색이 사용되고 실제 프롬프트에 선택된 기억이 들어간다.
**기능 검증이며 자연스러움 PASS가 아니다. 공유 연결 코드 변경은 병합 전 사람 검토가 필요하다.**

## 승인 범위와 보존

- 사용자 승인: Qwen 로컬 다운로드/실행, 캐릭터 기억 재색인, 웹 검색 연결 및 에이전트 재시작.
- DDL·페르소나/기억 원문·검색 순위/임계값·답변 생성 모델은 변경하지 않았다.
- 활성 페르소나 조각은 `always` 22개, `never_prompt` 18개다. 별도 검색 대상 조각은 없으며,
  상세 설정은 캐릭터 기억으로 분리돼 있다. 제작 지침이나 상시 성격을 중복 색인하지 않았다.
- 실제 사용자 대화를 읽어 일괄 임베딩하거나 장기 기억 worker를 활성화하지 않았다.
  앞으로 웹 질문의 검색용 임베딩은 로컬 Qwen으로 처리된다. 답변 생성은 기존 외부 LLM이다.
- 개발 DB 및 55433 DB는 수정하지 않았다.

## 모델과 실행 규격

- 모델 리비전: `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`.
- Python 3.12, sentence-transformers 5.1.2, transformers 4.57.6, torch 2.8.0.
- SentenceTransformer의 모델 제공 pooling 사용, L2 정규화, 기본 1024차원.
- 저장 문서는 원문 그대로 인코딩. 질의는 Qwen 공식 형식에 맞춘 영어 검색 지시문과
  `Query:`를 붙인다. 지시문은 문서 원문이나 대화 프롬프트에 쓰지 않는다.
- 로컬 API: `http://127.0.0.1:8788/v1/embeddings`. Loopback 바인딩과 로컬 Bearer 토큰.
  float/base64 OpenAI 호환 출력, 모델/차원/빈 입력 검증, 8192토큰 초과 입력은 절삭하지 않고 거절.
- 런타임은 다운로드된 모델만 읽는다. 모델 다운로드 때만 Hugging Face에 접속한다.
- Qwen 색인 125문서 6107토큰, 약 6.2초. 외부 임베딩 API 비용 0달러(로컬 자원 비용 별도).
- 사용자 모델 변경 전에 완료된 OpenAI 호출 1회는 8549토큰/약 $0.00017098이었다.
  그 벡터는 백업에만 남고, 현재 대상 125개에는 Qwen 벡터가 저장돼 있다.

## 기존 소유자 재사용과 변경 파일

`owner-found`: `DbSettingsProvider`가 DB 모델/URL/키 조회, `ChatService.prepare`가 검색 준비,
`PostgresPersonaStore.retrieveContext`가 캐릭터 검색, 기존 `persistContextEmbedding`이
모델/차원/원문해시 및 캐릭터 소유권을 확인한 색인 저장을 소유한다.
서빙 코드에서 캐릭터 이름이나 개별 문장에 따른 예외는 추가하지 않았다.

- `src/provider/llm-provider.ts`: 선택적 `embedQuery` 계약. 벡터와 그 호출의 모델명을 함께 반환.
- `src/provider/db-settings-provider.ts`: DB 설정 스냅샷을 요청마다 읽고 Qwen 질의만 지시문 처리.
  모델이 바뀌어도 벡터를 다른 모델로 잘못 표기하지 않도록 같은 조회 결과를 캡처한다.
- `src/chat/chat-service.ts`: 상수 환경 모델이 없어도 기본 제품 경로에서 질의 임베딩을 수행.
  캐릭터/사용자 기억 검색에 같은 벡터와 모델명을 전달. 오류/잘못된 차원은 단어 검색으로 대체.
- 위 provider와 chat-service의 테스트 파일: DB 모델 변경, 문서/질의 구분, DB 실패,
  실제 검색 경로 연결 및 임베딩 실패 대체 동작을 검증.
- `scripts/qwen-embedding-server.py`: 로컬 모델 HTTP 실행기. 기존 로컬 Qwen 서버가 없어 추가.
  공유 모델 제공자와 HTTP 진입점 검색에서 기존 실행기를 찾지 못함(`owner-absent`).

## 검증

- 변경 전 회귀 테스트: 누락된 `embedQuery`/빈 검색 벡터로 3개 실패 확인 후 구현.
- 변경 후 좁은 테스트 49개 통과, 전체 unit 418개 통과 / DB 통합 24개 미실행.
- typecheck / typecheck:eval / build 통과.
- 전체 lint 종료 코드 0: 기존 eval 결과 파일에서 warning 34개/info 13개.
  이번에 변경한 TypeScript 5개 파일의 좁은 lint는 진단 없이 통과.
- eval 테스트 101개 통과 / DB 필요 1개 미실행. 최초 실행은 샌드박스의 포트 바인딩
  제한으로 1개 실패했고, 네트워크 권한을 받은 재실행에서 통과했다.
- 로컬 HTTP: 잘못된 토큰 401, 다른 모델/1536차원/빈 입력 각각 400.
  실제 OpenAI SDK base64 응답 경로로 1024차원·유한값·단위 길이 검증.
- 제품 `buildContainer(...).chat.prepare` 4캐릭터 모두 `semanticStatus=used`.
  이 검증은 답변 생성/메시지 저장/장기 기억 생성을 하지 않는다.

모델/가상환경은 해당 디렉터리에 있으므로 테스트 중 이동/삭제하지 않는다.
색인 복구가 필요하면 새 내용 편집 여부를 해시로 확인하고, 이전 벡터·메타데이터와
임베딩 설정을 한 트랜잭션으로 함께 복원한다. 서로 다른 모델의 벡터를 섞지 않는다.
이전 OpenAI 설정은 1024차원 질의 연결이 없어 의미 검색 복구를 보장하지 않는다.
단순 기능 중단은 임베딩 서버 정지로 단어 검색 대체가 가능하며 대화/기억 원문은 보존된다.
