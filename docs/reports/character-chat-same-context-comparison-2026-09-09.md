따라서 D32의 짧은 답변이나 문제 표현 부재를 N1 지적 사항의 해결 증거로 쓰지 않는다.

이번 `before`는 **N1의 after**, 즉 재검수에 포함된 당시 개선안의 정확한 입력이다.
N1의 before나 D32의 before가 아니다. `after`는 현재 D31 최종 DB와 현재 런타임이
실제 HTTP 대화 경로에서 조립한 입력이다. 과거 출력과 새 출력을 비교하는 대신,
승인 후 양쪽 입력으로 답변을 새로 생성하도록 32요청을 동결했다.

## 동일하게 고정한 조건

한소이·서린·권도건·나희 각각 아래 네 문맥을 사용한다. 총 16쌍/32요청이다.

| 문맥 | 마지막 사용자 발화 | 당시 합성 관계 값 |
| --- | --- | --- |
| 인사 | ㅎㅇ | XP 0 / level 1 |
| 근황 | 뭐해? | XP 120 / level 2 |
| 라면 | 일 얘기는 됐고 ㅋㅋ 나 아까 라면 먹다가 흰 티에 국물 튀었어 | XP 320 / level 3 |
| 알람 | ㅇㅇ 마지막 건 끈 기억도 없어 | XP 600 / level 4 |

라면 앞에는 `오늘 일은 어땠어?` → 고정 응답 `좀 정신없었어요.`가 있다.
알람 앞에는 `알람 다섯 개 맞췄는데 다 끄고 잤어` → 고정 응답 `다섯 개를 다요? ㅋㅋ`가 있다.
이전 응답도 원본 그대로이며 최신 모델이 생성한 답변이 아니다.

- 원래 fixture의 cases SHA256과 16개 N1-after 요청 hash를 대조했다. 대화 원문은 재작성하지 않았다.
- 시각은 **2026-09-08 15:00, Asia/Seoul**, 합성 마지막 접촉은 하루 전이다.
  공유된 과거 대화나 현재 활동이 추가로 존재한다는 뜻이 아니다.
- 양쪽의 실제 시각·친밀도 안내 문구까지 동일함을 확인했다.
- 모델 `xiaomi/mimo-v2.5-pro`, temperature 0.7, top_p 0.95, max_tokens 8192,
  Xiaomi/fp8 한정·fallback 없음·reasoning 제공자 기본값 조건을 동일하게 동결했다.
- 사용자 학습 메모리·대화 요약·핵심 메모리는 없다. 빈 임베딩 대역을 사용했다.
  실제 사용자 ID나 대화 내역은 읽거나 포함하지 않았다.
- 요청 순서를 결과 생성 전에 고정하고 구/신 입력 선행 순서를 8쌍씩 균형 배치했다.

두 조건 사이에는 누적된 공통 지침·문맥 배치·페르소나 구조/본문·메모리 선별 변경이 함께 있다.
**전체 개선 묶음 비교**이며, 특정 문구·구조 하나의 인과 효과나 모델 자체의 결함을
분리해서 입증하는 실험은 아니다. 문맥당 1개씩 생성하므로 안정적인 개선율도 확정할 수 없다.

## 준비 단계에서 확인한 것

- 최신 입력 16건을 `createApp → ChatService → PostgresPersonaStore → FakeProvider`의
  기존 경로로 캡처했다. 대화 문맥·시각·관계·모델 설정은 구/신 16쌍 모두 일치한다.
- 최신 16입력에서 추가 배경·캐릭터 사건 메모리 선택은 0건이다. 상시 성격·말투는 유지된다.
  불필요한 기억을 넣지 않은 이 결과를 필요한 기억 회수 능력 전체의 증명으로 확대하지 않는다.
- 입력의 문자 단위 확인: `셀렉`은 구4/신0, `오, 왔네요`는 구4/신0,
  `오, 왔어요`는 구0/신0이다. **단어 금지나 응답 사후 교정 기능을 새로 추가하지 않았다.**
  입력에 없는 표현도 모델이 생성할 수 있으므로 재발 방지 판정이 아니다.
- 16요청 JSON의 UTF-8 크기 합은 303,884 → 184,368 bytes다.
  토큰 수·응답 속도·실제 비용·자연스러움 측정치가 아니다.
- 전용 로컬 DB에 `default_transaction_read_only=on`으로 접속했다.
  준비 전후 및 별도 재검증에서 D31 최종 source·fragment·canon 내용이 동일했다.
  기존 결과·사용자 제출·관련 코드·이번 준비 스크립트를 포함한 보호 대상 515파일의 hash도 보존했다.
- 문맥·샘플링·시각·관계·요청 hash를 각각 훼손한 5개 검사에서 검증기가 거부했다.
- 관련 제품 회귀 105개, 검수 회귀 5개 통과. 전체 저장소 check는 이번에 재실행하지 않았다.

준비 단계 당시에는 새 LLM 호출·개발 서버 접근·DB 쓰기·DDL·웹 게시·commit/push가 모두 0이었다.
현재 실행/게시 상태는 위 실행 기록을 따른다. N1 재검수, 미검수 D32, 신규 쌍별 검수가 접수된 D35는 구분한다.

## 준비 시 확정했던 실행 경계

기존 D32의 32답변 실행 승인은 소진됐다. 이번 준비 manifest의
`paidExecutionApproved=false`는 준비 당시 기록으로 보존했다.
이번 별도 범위 승인 뒤 **로컬 Mac → OpenRouter → Xiaomi**로 전송했다.
범위는 동일 4캐릭터의 설정·캐릭터 기억과 합성 문맥, 최대32답변·총$1·재시도0이다.
현재 모델/제공사/가격/파라미터를 실행 직전에 재확인해야 한다.
입력 byte 수와 가격 제한으로 계산한 보수적 예약 합은 **$0.571806**이며 청구액이 아니다.

이전 실행처럼 개발 설정에서 URL·모델·키를 읽을 필요가 있다면 해당 3항목만 read-only로 읽고,
키는 프로세스 메모리·인증 헤더에만 사용한다. 개발 서버로 대화를 중계하거나 DB를 쓰지 않는다.
새 packet ID로 원문과 전체 합성 문맥을 제공한다. 과거 N1의 A/B·PASS를
옮기거나 오래된 사이트 첫 화면을 새 결과라고 안내하지 않는다. 현재 새 검수 링크는 상단에 있다.
