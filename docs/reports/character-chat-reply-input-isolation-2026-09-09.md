# D36 — 공통 응답 지침과 말투 자료의 분리 비교 준비

2026-09-09. **로컬 수정 후보와 비교 입력 준비 완료. 실제 LLM 답변0·새 사용자 판정0.**
제품 코드, 로컬/개발 DB, 원격 검수 화면에는 적용하지 않았다. 이번에 바꾼 것은 비공개 실험용
입력의 공통 지침 본문과 캐릭터별 핵심 말투 문단이다. 자연스러움이 개선됐다는 결론은 아직 없다.

## 왜 이 두 부분을 나누었나

[D35 사용자 검수](character-chat-same-context-comparison-2026-09-09.md)에서 이전안5/최신안3,
둘 다 나쁨6/동률1/판단 보류1이었다. 알람 후속은 네 캐릭터 모두 both_bad다.
사용자의 수정 제안에서는 근황 답변 뒤의 불필요한 말도 검토 대상으로 드러났다.

실제 입력을 확인한 결과는 다음과 같다.

- 이전 사용자 발화와 캐릭터 답변이 들어 있다. 이번 로컬 HTTP 재생에서도 D35 최신 입력16개를
  정확히 재현했다. **이 비교의 실패를 이전 대화 누락으로 설명할 수는 없다.**
- 공통 지침에는 이미 짧은 후속 발화를 앞 대화와 함께 읽기, 질문은 선택, 억지 비유를 피하기가
  들어 있다. 해당 규칙이 없었던 것이 아니다. 규칙이 실제 답변에서 잘 작동하는지는 별개다.
- 이 입력들에서는 추가 배경·캐릭터 사건 기억·사용자 기억·요약·핵심 기억이 선택되지 않았다.
  불필요한 기억 주입이 이 결과의 유일한 원인이라는 설명도 지지되지 않는다.
- 캐릭터의 성격 자료는 서로 다르지만, 말투 설명에는 짧음·담백함·장난의 절제 등 유사한 지침이
  반복된다. 이것이 반응 수렴의 원인인지는 아직 모른다. 말투 문단을 독립적으로 비교해야 한다.

## 준비한 네 조건

| 조건 | 공통 응답 지침 | 핵심 말투 문단 | 나머지 입력 |
| --- | --- | --- | --- |
| control | 현재 그대로 | 현재 그대로 | 고정 |
| policy-only | 수정 후보 | 현재 그대로 | 고정 |
| voice-only | 현재 그대로 | 수정 후보 | 고정 |
| combined | 수정 후보 | 수정 후보 | 고정 |

기준은 **D35의 최신안(D31 최종 자료와 현재 런타임)**이다. D35의 이전안/N1-after로 되돌린
비교가 아니다. 공통 지침만의 차이는 control↔policy-only와 voice-only↔combined,
말투만의 차이는 control↔voice-only와 policy-only↔combined로 볼 수 있다.
공통 지침 전체의 표현·길이·강조점을 함께 바꾸므로 특정 한 문장의 인과 효과까지 분리하지는 못한다.

### 공통 지침 후보에서 바꾼 점

기존11개 항목을6개 항목으로 다시 썼다. 추가 금지어 목록이나 특정 상황의 정답 대사는 넣지 않았다.

- 주제만 맞추는 것보다, **직전 대화에서 새로 보탠 내용에 반응**하도록 강조한다.
  이미 말한 결과를 다시 설명하거나 이름 붙이고, 이미 받은 답을 되묻는 반응을 피하도록 한다.
- 질문·조언·설명을 덧붙일 때에는 구체적인 대화상 이유가 있어야 한다. 답이 끝났으면 멈출 수
  있지만, 필요한 긴 답변까지 제한하지는 않는다.
- 성격은 같은 사건에서 무엇을 눈여겨보고 어떤 태도를 보이는지에 드러내며 매 턴 수행할
  과제로 만들지 않는다. 짧은 잡담에도 자기 반응을 보탤 여지를 남긴다.
- 한국어 문장 안의 지시 대상과 앞뒤 연결을 분명히 하고, 재치 있는 비유·마무리를 억지로
  만들지 않도록 한다.
- 현재 활동·공유된 과거·사용자 감정을 지어내지 않는 경계, 실제 관계에 따른 말투,
  예문·게시물과 실제 대화를 구분하는 원칙은 유지한다.

이 공통 구간의 크기는3,215→2,041 UTF-8 bytes다. 입력 크기일 뿐 토큰·속도·비용·품질 측정치가 아니다.
실제 후보 영어 원문은 비공개 `candidate-content.json`의 `commonPolicy`에 보관했다.

### 말투 후보에서 바꾼 점

캐릭터마다 핵심 `voice` 문단1개, 총4개만 새로 썼다. 말투 문단이 둘인 소이·서린은 나머지 문단을
그대로 두었다. 캐릭터 ID·직업·성격·가치관·관계·안전 경계·사건 기억의 원문은 변경하지 않았다.

| 캐릭터 | 말투 후보의 중점 | 이 단계에서 바꾸지 않은 것 |
| --- | --- | --- |
| 한소이 | 낯가림 속의 관심, 소소한 일에 조심스럽게 자기 생각을 보태는 다정함 | 수더분한 존댓말, 기존 금지·사생활 경계 |
| 서린 | 과장 없이 자기 취향을 드러내고 무심한 말 사이에 관심을 보이는 태도 | 기존 이모지·표현 지침, 초면과 익숙한 관계의 구분 |
| 권도건 | 자신 있는 직접성, 실수 인정, 잡담과 도움 요청을 구별하는 태도 | 코치라는 정체성, 상대를 평가·훈계 대상으로 보지 않는 경계 |
| 나희 | 자기 취향에 솔직한 여유, 칭찬을 받아들이고 선을 분명히 하는 태도 | 기존 성격·동의·사생활·성적 표현 경계 |

이는 기존 성격을 말투 문단으로 옮긴 **실험용 해석**이며 사용자 승인 정답이나 검증된 개선이 아니다.
캐릭터 이름/ID에 따라 답변을 분기하는 제품 코드는 만들지 않았다. 후보 문단에는 별도 실험 ID를
부여하고 `voice-diff.json`에 원래 block ID·본문 hash와 후보 ID·본문 hash를 함께 남겼다.

## 조립·검증 방식과 한계

- D31의 보관된 DB 스냅샷을 `StubPersonaStore`에 넣고 기존 `createApp → ChatService →
  Persona Router → renderPersonaBlock → FakeProvider` 경로로 요청을 조립했다.
  이번 reader는 **저장된 스냅샷 재생**이지 실제 DB 재조회가 아니다.
- 현재 자료16개와 말투 후보16개, 총32개 HTTP 입력을 캡처했다. 현재 자료의16개는
  실제 D35 최신 요청과 동일하다. 말투 후보는 해당 문단만 바뀌었는지 별도로 대조했다.
- 공통 지침 후보는 캡처된 system 메시지의 정확한 공통 구간만 교체한 **오프라인 요청 후보**다.
  제품의 `NATURAL_REPLY_POLICY`를 변경하거나 새 설정 기능을 추가한 것이 아니다.
- 4명×4문맥×4조건=64입력을 준비했다. 모델·샘플링·전체 대화 원문·시간·관계·문맥 배치·
  기억·그 밖의 페르소나 자료는 조건 간 동일하다. system 외 메시지는 byte-equivalent다.
- 일차 비교 후보는 **알람·근황 ×4명×4조건=32답변**이다. 요청 순서는 출력 전에 동결하고
  네 조건이 각 순서 위치에 두 번씩 오도록 배치했다. 인사·라면32입력은 보조 회귀용이며
  일차 유료 실행 범위에 포함되지 않는다.
- 입력/이전 메시지/샘플링/시각/추가 지침/누락된 지침 변경6개를 넣었을 때 검사기가 거부했다.
  이후 별도 재검증에서 조건 라벨·변경 축·64입력의 대응·32개 일차 순서 균형도 확인했다.
- 관련 제품 테스트123개, 검수 테스트5개 통과. 보호대상518파일의 hash와 원래 사용자 제출을
  보존했다. 전체 저장소 검사, 실제 모델 생성, 긴 대화·새로운 문맥·반복 표본 검증은 하지 않았다.
- 새 후보에 D35의 선호·both_bad·개별 PASS/FAIL을 복사하지 않았다. 더 짧아졌다는 이유나
  검사 통과만으로 자연스럽다고 판정하지 않는다.

## 원인 가설과 다음 검증

| 가설 | 현재 근거·상태 | 구분할 검증 |
| --- | --- | --- |
| 과거 메시지가 빠졌다 | 이번 고정 입력에서는 배제 | D35 요청과 현재 HTTP 재생의 이전 발화 일치 확인 완료 |
| 불필요한 기억이 유일한 원인이다 | 이번 입력에서는 지지되지 않음 | 선택 기억이0인 입력에서도 사용자 지적 답변이 나옴 |
| 공통 지침의 표현·강조가 효과적이지 않다 | 미확정 | 공통 지침만 다른 실제 답변을 비교 |
| 말투 설명이 개성 있는 반응으로 잘 이어지지 않는다 | 미확정 | 말투 문단만 다른 실제 답변을 비교 |
| 모델·문맥 배치·친밀도 지침이 원인이다 | 미확정·이번에는 고정 | 두 변경 축으로 개선되지 않으면 후속 원인 분리 대상으로 검토 |

일차 실험은 어느 변경이 유효할지 확인하기 위한 작은 비교다. 각 조건당 한 답변만 생성할 계획이므로
안정적인 개선율이나 일반적인 모델 성능을 입증하지 못한다. 같은 답변을 여러 대조에 사용해도
새 독립 표본으로 중복 계산하지 않는다. 사용자의 실제 선택·코멘트만 반영하고 개별 PASS를 추정하지 않는다.
선택된 후보는 이후 새로운 문맥·반복 표본·더 긴 대화에서도 확인해야 한다.

## 보관 위치·실행 경계

이번 범위에서는 외부 네트워크 호출을 막은 로컬 대역만 사용했다. 모델/embedding 실호출·DB 접근/
쓰기·DDL·개발 서버 접속·웹 게시·commit/push0. 메모리 정정·망각 작업도 계속 보류한다.

**추가 유료 실행 승인=false.** 이전 D35의32회 승인은 소진됐으며 재사용하지 않는다.
새 승인 후보 범위는 로컬 출발 OpenRouter/Xiaomi(mimo-v2.5-pro), 동일4명 설정과 합성 문맥만,

실행 전 현재 제공자·가격·허용 파라미터와 비용 상한을 다시 확인한다. 인증 설정이 필요하면
기존 연결의 URL·모델·키3항목만 read-only로 사용하고, 키를 산출물·로그에 남기지 않는다.

제품의 지침·말투 저장 소유자는 변경하지 않았다. 입력 보존과 변경 축 분리라는 검증 사실은
이 보고서/기존 인계에 기록하고, 미확정 원인이나 후보의 자연스러움은 확정 지식으로 승격하지 않는다.
