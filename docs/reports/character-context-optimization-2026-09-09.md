# D31 — 페르소나·메모리 내용과 선택 주입 개선

## 목표와 적용 범위

이번 목표는 저장 구조 통과가 아니라 **성격을 유지하면서 지금 대화에 필요한 내용만 사용해
자연스럽게 답하는 것**이다. 사용자 요청으로 페르소나와 캐릭터 메모리의 내용까지 수정한다.
기존 네 캐릭터와 전용 로컬 DB를 사용하며 원문·이전 사용자 검수·D30 증거는 보존한다.
새 DDL, 개발 DB, 배포, 정정·망각, 자동 사용자 PASS 생성, commit/push는 제외한다.

계획:

1. 공식 서비스 문서·원논문과 D30 실효 입력을 대조한다.
2. 상시 정체성/성격/말투/경계는 간결하게, 상세 취향·이력·사건은 조건부 자료로 정리한다.
   기존 API를 통해 로컬 DB에 적용하고 before/after/rollback을 보관한다.
3. 공통 주입 경로에서 중복 프로필, 회수량, 짧은 지시적 후속 질문을 개선한다.
   캐릭터별 이름/ID 분기 없이 기존 소유자를 확장한다.
4. 같은 문맥에서 D30/내용만/선별만/결합 입력을 비교한다. 필요한 사실의 회수 누락과
   무관한 정보의 주입을 모두 검사한다. 실제 답변 비교는 동일 모델 설정의 전후 16쌍이다.
5. 전체 관련 테스트·빌드·문서 검증. 실제 모델 답변과 사용자 검수 전 자연스러움 PASS는 없다.

단순 압축률·토큰 절감은 성공 기준이 아니다. 핵심 성격/경계 보존, 사실 누락·중복·주제 누출,
부자연스러운 한국어, 획일적인 반응, 관계에 맞지 않는 친밀함을 함께 확인한다.
미검수·판단 보류·쌍별 선호는 기존 의미를 유지한다.

## 결정·검증 경계

- `user-confirmed`: 내용 최적화와 구조/내용/필요한 주입의 자연스러움 테스트.
- `agent-assumed`: 사실과 성격의 의미를 유지한 편집, bounded keyphrase 회수와 분량 제한.
  한국어 지시적 후속 질문은 바로 전 사용자 발화에만 제한해서 보완한다. 일반 의미 이해가 아니다.
- `preserve-current-behavior`: 일반 proxy, custom selector, 기존 untyped persona, 사용자별 기억
  저장/권한/정정·망각, 모델 sampling 설정, 기존 사용자 제출.
- `recommended-unconfirmed`: 새 외부 비교 실행. 4캐릭터 설정·캐릭터 메모리·합성 문맥만

### 실행 위치와 전송 경계

- 코드: 현재 Mac의 `opod-agent` 로컬 작업 사본. 개발 서버에 반영하지 않았다.
- 데이터: 이전에 만든 전용 로컬 DB `127.0.0.1:55433/opod_persona_memory_local`.
  종료돼 있던 `opod-persona-memory-local-20260908` 컨테이너만 재시작했다.
  기존 D30 상태를 확인한 뒤 적용했으며, 개발 DB를 다시 dump하거나 수정하지 않았다.
- 관리 API도 로컬 Mac의 임시 loopback 서버다. 실제 admin API를 통해 저장하고 종료했다.
- 이번 입력 검사는 로컬 HTTP 대화 경로 → 실제 DB reader → FakeProvider를 사용했다.
  FakeProvider의 고정 문자열은 **입력 경로 검사 표식**이며 실제 LLM 답변이 아니다.
- 승인을 받은 뒤 실행할 실제 답변 비교의 경로는 **로컬 Mac → OpenRouter → Xiaomi
  `mimo-v2.5-pro`**다. 개발 서버를 경유하지 않는다. 4캐릭터 설정·캐릭터 메모리와 표시된
  합성 대화만 대상이며 실제 사용자 대화·사용자별 학습 기억은 포함하지 않는다.
  이번에는 실제 LLM/embedding 호출, 개발 서버 접속, 새 원격 게시 모두 0이다.

원문 source45개 중 **23개**를 편집했다. 조각은72→78(상시33→31/조건부22→30/제외17유지),
canon79행은 유지하면서 본문20행, 회수 정책24행을 변경했다. 상시 canon은11→0이다.

성격 의미를 유지하려는 편집이지만 의미적 동등성이 자동 증명된 것은 아니다. 성격 유지 검토가 필요하다.

성격은 같은 공통 형식 안에서 다르게 남겼다. 아래는 **저장된 후보의 일부**이지 생성 답변이 아니다.

- 한소이: “칭찬은 쑥스럽지만 고맙고, 비판은 겉으로 담담해도 오래 생각한다.”
- 서린: “칭찬이 좋으면 호들갑 대신 은근히 티가 난다.”
- 권도건: “자기 속도를 남에게도 기준으로 삼거나, 잘못된 판단을 체력으로 밀어붙이려는 것이 약점이다.”
- 나희: “칭찬을 자연스럽게 받아들이며 일부러 겸손하거나 순진한 척하지 않는다.”

메모리 편집 예: “직접 1차 셀렉”을 반복하던 업무 설명은 캐릭터 메모리의
“평소 촬영이 끝나면 원본을 두 곳에 보관하고 쓸 사진을 직접 고른다.”로 정리했다.
배경에는 의상 반납/파일 정리 등 보완 정보만 남겼다. 현재 일정인지 구별하는 지침은 공통
문맥 섹션이 맡으며, 각 사실에 “오늘 하고 있는 일이라는 뜻은 아니다”를 반복하지 않는다.
조건부 자료의 전문 표현을 모두 금지한 것은 아니다. 전문적인 질문에서는 필요한 말이 될 수 있다.

### 공통 선택 경로 변경

기존 `character-recall.ts`를 확장했다. 런타임에 특정 캐릭터 이름/ID 분기는 없다.

- 명시 키와 맞는 자료만 회수하고, 더 긴 키가 맞은 자료를 우선한다. 동점은 source 순서다.
- lore/canon 각각 최대4개, 본문 합계 **1,200 Unicode code point**를 넘지 않는다.
  토큰 제한이 아니며 두 소유자의 합계는 최대2,400자 + 제목/공통 지침이다.
  큰 항목은 자르지 않고 건너뛰고, 각 선택 목록 안의 정규화된 동일 본문은 한 번만 넣는다.
- `말고`, `됐고`, `얘기/이야기…그만`을 만난 발화에서는 마지막 중단 표현 뒤의 키만 본다.
- 현재 발화에서 키를 찾지 못한 짧은 지시적 질문(“그거…”, “그때…”, “거기…” 등)은
  바로 앞 최대2개 메시지 안의 사용자 발화1개를 보완 근거로 사용한다.
  최신 발화120자/이전 사용자 발화의 끝256자까지만 사용하고, 현재 키나 주제 종료가 우선한다.
  assistant가 지어낸 소재를 회수 쿼리로 사용하지 않는다.
- selector seam의 `previousQuery`는 optional이다. custom selector/일반 proxy/사용자 기억
  검색에는 같은 규칙을 강제하지 않는다. 공통 답변 지침·모델 sampling 값은 이번에 바꾸지 않았다.

이는 **제한된 한국어 키 휴리스틱**이다. 따옴표 안의 말·모든 부정·의역·여러 지시 대상·여러 턴
뒤의 참조를 해결하지 못한다. 키가 없거나 너무 큰 사실은 누락될 수 있다. 다른 사실을 같은
말로 표현한 의미적 중복도 자동 해결하지 않는다. 이 한계를 “문맥 이해 완료”로 보고하지 않는다.

### 같은 문맥 4조건 검사

4캐릭터 × 인사/칭찬/커피/지시적 후속/주제 종료/새 주제/무관한 발화/과거 회수의8문맥 ×
4조건 = **128입력**을 저장했다. 모두 같은 합성 이전 대화와 고정 시각을 썼다.

| 조건 | 후속 질문에 커피 정보 있음 | 커피 주제 종료 뒤에도 커피 정보 남음 |
| --- | ---: | ---: |
| D30 기존 | 2/4 | 4/4 |
| 내용·저장 분류만 수정 | 0/4 | 4/4 |
| 선택·프로필 주입만 수정 | 4/4 | 2/4 |
| 둘을 결합 | 4/4 | 0/4 |

숫자는 system + 해당 턴에 새로 주입한 문맥의 **정보 존재 검사**다. 원래 대화 기록의 커피
언급을 삭제한 것이 아니며, 답변 합격률·회수 전반의 정확도·사용자 판정도 아니다.
내용만 조건의0/4는 원래 상시 기억을 조건부로 옮겨도 후속 참조가 없으면 필요한 정보까지
빠짐을 보여준다. 선택만 조건의2/4는 상시 자료를 그대로 두면 선택기로 제거할 수 없음을 보여준다.
단순히 프롬프트를 짧게 만드는 것만으로는 두 문제가 함께 해결되지 않았다.

`selection-only`는 동결한 D30 Persona 객체를 읽는 Store replay이고, 나머지3조건은 실제
로컬 DB reader다. 그 차이를 숨기지 않는다. 전체 서비스의 운영 설정과 개인화까지 재현한 것은 아니다.

최종 내용 검토에서 조건부 배경1행의 잔여 셀렉/중복 업무 설명과 메모리2행의 중복 지침을
