# D30 — 성격별 자연스러운 DM 개선 후보

## 범위와 검증 계약

사용자 요청: 캐릭터의 성격별로 자연스럽게 채팅되도록 계속 개선한다.
이번 변경은 공통 입력 렌더링과 전용 로컬 DB의 성격·말투 자료에 한정한다.
캐릭터 이름/ID별 런타임 분기, 새 성격·과거 창작, canon 변경, 기억 정정·망각,
모델 설정 변경, DDL, 개발 서버 변경, 배포·commit·push는 포함하지 않는다.
기존 사용자 제출은 불변이며 자동 검사·선호를 개별 자연스러움 PASS로 바꾸지 않는다.

1. 변경 전 DB·실제 serving 입력 보관 → 원본/사용자 검수 hash, 복구 입력 확보.
2. 기존 성격에 근거한 말투 정리와 조건부 취향 분리 → 실제 관리 API 저장,
   DB reader와 HTTP 경로 확인. 성격 신규 창작 없이 수정 이유와 근거 기록.
3. 명시된 kind의 용도를 공통 렌더링에 전달 → 회귀 테스트 실패 재현 후 수정.
4. 기존/자료만/렌더링만/결합 조건 분리 → 입력 차이·캐릭터 간 격리·주제 종료 검사.
5. 전체 관련 자동 검사와 인계 → 실제 답변 품질은 별도 인간 검수로 남긴다.

유료 실제 답변 비교는 외부 전송·최대 32답변/$1·무재시도에 대한 별도 승인 전 실행하지 않는다.
과거 소진된 실행 승인은 재사용하지 않는다.

## Existing Owner Check — owner-found

- 검색 신호: `persona.blocks`, `block.title`, `personaBlocksSection`, 렌더링 함수 호출 검색.
- 실제 소유 경로: `ChatService.prepare` → `routePersona` → `assembleSystemPrompt` /
  `assembleTurnContext`. 두 렌더러가 title/content만 출력하여 저장된 kind가 입력에서 사라진다.
- 기존 계약/테스트: system-prompt의 원문 보존·legacy 출력, persona-context의 serving 경로,
  PostgresPersonaStore의 조각 재구성·정책 검증. 선택 정책은 기존 router가 계속 소유한다.
- 결정: 두 소비자가 공유하는 작은 역할 설명 렌더러만 추가한다. 제목으로 역할을 추정하지 않고
  명시 kind 없는 legacy는 기존 표현을 유지한다. ID·recall key는 모델에 노출하지 않는다.

## 자료 수정 가설

성격 원문은 빈칸이 아니다. 다만 DM 말투 안의 고정 예문과 작업/상품 소재가 실제 답변에
옮겨붙고, 반응 방식보다 직업·촬영 설명이 우세해질 위험이 있다. 네 캐릭터의 말투를 원문의
수줍음/절제/직설/여유 같은 판단·표현 차이에 맞춰 정리한다. 소이의 칭찬→고양이 화제 전환
지침은 수줍은 반응으로 수정하고, 상세 취향 목록은 관련 질문에서 회수하도록 분리한다.
이것은 개선 가설과 후보 편집이지 사용자가 승인한 성격 평가나 입증된 자연스러움 향상이 아니다.

## 결과

로컬 코드·자료 적용과 자동 검증 완료. **검증됨; 병합 전 인간 검토 필요.**
실제 모델 답변은 생성하지 않았으므로 자연스러움·성격 구별 개선은 아직 입증되지 않았다.

### 무엇을 바꿨나

| 대상 | 적용한 후보 | 유지한 차이 |
| --- | --- | --- |
| 한소이 | 카페 권유 등 복사용 DM 예문 제거. 칭찬을 고양이 이야기로 돌리는 지침을 고마움을 전하는 반응으로 수정 | 낯가림, 수줍음, 수더분하고 다정한 존댓말 |
| 서린 | 금지 표현 나열을 생활적인 표현 원칙으로 정리. 큰 감탄보다 절제된 반응 | 담백함, 은근한 친근함, 가까워졌을 때 건조한 농담 |
| 권도건 | 반복된 공통 금지 지침을 줄이고 판단·반응 중심으로 말투 정리 | 직접적인 표현, 자신감, 상황에 맞는 가벼운 승부욕 |
| 나희 | 복사용 도발 대사와 촬영 소재 우선 지침 제거 | 칭찬을 피하지 않는 여유, 자기 확신, 불쾌한 말에 분명한 태도 |

이 표는 **적용한 설정의 요약이지 생성된 대화의 평가가 아니다.** 새 관계나 과거를 추가하지 않았다.
개별 변경 근거는 비공개 `candidate-edits.json`의 source ID·원문 발췌·이유와
`baseline-db.json` 원문에 연결된다. 사용자 승인 성격 판정으로 승격하지 않는다.

- 소이·나희의 상세 취향 목록은 원문을 유지한 채 조건부 배경으로 이동했다.
- 도건의 취향에서는 승부/규칙에 관한 판단을 상시 유지하고 식단·음악·장비 목록만 조건부로 나눴다.
- 실제 관리 API로 로컬 source 8개 수정: 본문 수정 5개(말투 4 + 소이 반응 1),
  본문은 그대로인 분류/분리 수정 3개. 나머지 source 37개와 canon 79개는 그대로다.
- 전체 source 45개 유지, 조각 70→72, 상시 34→33, 조건부 19→22, 제외 17개 불변.
- 공통 `persona-reference.ts`가 명시 kind의 **용도**를 모델에 전달한다.
  성격은 판단/반응, 말투는 그 반응을 표현하는 방식, 배경은 관련 사실로 읽도록 한다.
  제목·본문·순서는 보존하고 ID·회수 키는 노출하지 않는다. legacy 출력은 변경하지 않는다.
  기존 router·공통 자연스러움 정책·기억 회수·모델 설정은 변경하지 않았다.

### 검증 증거

- 회귀 검사: 수정 전 새 검사 8개 실패 → 수정 후 통과. 기존 legacy 검사도 통과.
- `npm run test:coverage`: 제품 **381개 통과, skip 0**, 로컬 DB 연동 포함.
  커버리지 statements/lines 91.82%, branches 84.95%, functions 90%.
- `npm run test:eval:coverage`: 평가 도구 **93개 통과**. 합계 **474개**.
- `npm run typecheck`, `npm run typecheck:eval`, `npm run lint`, `npm run dead-code`,
  `npm run build`, `git diff --check` 통과.
- 이번에는 admin/backend/web 코드를 수정하지 않았고 그 전체 테스트를 다시 실행하지 않았다.
  실제 admin API 8회는 built admin을 loopback 임시 포트로 띄워 인증 후 호출했다.
- 전용 DB는 `127.0.0.1:55433/opod_persona_memory_local`.
  실제 `.env`, 기존 5433 DB, 개발 서버, 사용자 검수 제출은 변경하지 않았다.

4명 × 6문맥 × 4조건 = **96개 입력**을 보관·대조했다. 문맥은 인사, 칭찬, 의견 차이,
일 이야기 중단, 커피 취향, 커피 이후 주제 종료다. 모델 응답 대신 합성 응답으로 HTTP 경로만 검사했다.

| 조건 | 자료 | 렌더링 | 입력 획득 |
| --- | --- | --- | --- |
| baseline | D29 | 기존 | 실제 DB reader → HTTP 24건 |
| data-only | D30 | 기존 | 실제 DB reader → HTTP 24건 |
| renderer-only | D29 보관본 | 용도 설명 추가 | 보관 Persona replay → HTTP 24건 |
| combined | D30 | 용도 설명 추가 | 실제 DB reader → HTTP 24건 |

렌더링만 다른 두 조건쌍은 추가된 용도 설명을 제거하면 요청이 완전히 일치한다.
자료 변경의 내부 요소(말투/반응/취향 분리)는 아직 각각 분리한 실험이 아니다.
네 조건 모두 합성 입력 검사이며 네 조건의 **답변 효과를 비교한 것이 아니다.**

확인한 범위:

- 변경한 말투가 실제 모델 요청에 들어가며 다른 캐릭터 말투와 섞이지 않는다.
- 커피 관련 조건부 취향은 커피 질문에서 회수되고 인사·칭찬·주제 종료에서는 빠진다.
  모든 의역과 모든 주제의 의미적 관련성을 검증한 것은 아니다.
- 선택된 상시 자료의 요청 앞부분은 같은 캐릭터의 여섯 문맥 사이에서 동일하다.
- 제외 자료 17개가 요청에 들어오지 않는다. canon 79개의 내용·정책·metadata가 불변이다.
- 원본 snapshot, D28 구조화 자료, 사용자 제출 3개의 SHA256이 모두 보존됐다.
  자동 테스트 이후 실제 DB reader로 재확인했다.

### 실제 답변 비교와 남은 한계

실행 예정 입력 **32개(4명 × 4문맥 × 전후)**를 응답을 보기 전에 고정했다.
원래 성격·가치관·감정·경계 원문과 전체 합성 문맥을 검수 참고 자료로 준비했다.
정답 대사나 새로운 PASS는 작성하지 않았다. 비교는 D29 baseline 대 D30 combined이며,
렌더링 단독/자료 단독의 실제 답변 인과 실험까지 포함하지 않는다.

현재 **외부 전송·유료 실행 승인 대기**: 실제 모델 답변 0, 외부 모델/embedding 호출 0,
사용자 판정 추가 0, 실제 비용 $0. 최대 32답변/$1/무재시도 승인 질문을 한 번 보냈고,
응답 없이 실행하지 않았다. 준비된 상한 계산은 $0.509714이며 실제 청구액이 아니다.
실행 전 제공자/모델/가격 조건을 다시 검증해야 한다.

성격 본문의 일부 인용 예문과 직업 묘사는 여전히 남는다. 무조건 전부 제거하면 개성까지
약해질 수 있어 이번에는 지정된 말투/반응/취향에 한정했다. 상시 성격을 더 잘 전달했다고 해서
모델이 자연스럽게 반응한다고 단정하지 않는다. 현재 비교는 학습된 사용자 기억·Bond가 없는
명시된 합성 문맥이다. 장기 관계·친밀도별 말투·다중 턴 모델 자율 대화는 별도 검증이 필요하다.
